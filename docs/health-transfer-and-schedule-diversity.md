# 桌面版健康传递与日程避重（二改）

## 健康传递

HealthTransferInput 嵌入现有 HealthShortcutReceiver，通过显式粘贴或 JSON 文件预览数据；最终保存仍由原接收器处理，包括睡眠去重、快照写入、角色主动消息同步打脏及 UI 刷新事件。预览不会写库。

parseHealthTransfer 支持原始 JSON、URL 编码 JSON、已有 `#health-import=` 完整链接。完整链接只解析 fragment，不导航、不请求对应站点。沿用 parseHealthShortcut 的版本、日期、指标与体积校验。serializeHealthTransfer 只包含健康载荷，不含角色或应用备份。

不自动读剪贴板，不新增中转服务器，不尝试访问另一浏览器 / 主屏幕 App 的隔离存储。手动粘贴与文件导入作为权限后备路径。既有角色数据读取授权与 fire_pack 同步规则不变。

## 日程避重

generateDailyScheduleForChar 保持原有缓存、角色时区、世界书及私聊上下文管线。在一次日程模型请求之前，按已解析的角色本地日期读取该角色过去七个日历日的 `daily_schedule`；强制重生成时也读今日旧版本。

历史只包含有限长度的时间、活动及描述，不读全体角色，不把旧计划视作已完成事实。追加提示要求保留明确固定职责，但变化可自由安排部分的具体目标与进展；不能仅换同义词。每日提示方向只是可舍弃的参考，意识系不虚构身体活动。JSON 输出结构、API 路由和调用次数不变，不因相似自动重试。

历史读库失败时退为无历史提示；不清理、不迁移旧日程，不自动重生成今天。近七天日期运算针对角色日期 key 的日历加减，不将墙上时间当作真实时间戳再次做时区转换。
