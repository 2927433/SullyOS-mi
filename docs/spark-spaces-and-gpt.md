# Spark 独立空间与 GPT 文生图（二改）

## Spark 边界

原版把动态放在同一 social_posts 表内，刷新随机选择多个角色，评论可用其他角色补位；并不是所有角色会自动读取全库，但生成请求可能混合多个世界。

本版保留同一 IndexedDB 表，通过 SocialPost.sparkScopeCharId 做逻辑隔离。新动态及用户笔记写入当前空间；请求只选择当前角色并装载其世界书。切换空间取消未完成的刷新 / 评论请求。分享仅允许发到本空间角色的私聊，清理只删除当前空间的记录。不新增服务端共享数据库。

没有 sparkScopeCharId 的旧动态归入只读旧记录，不推测归属、不复制到任一新空间、不参与生成。用户可以显式删除旧记录；过去已转发到私聊的卡片及已生成记忆不自动改写。

## 已确认社交网

CharacterProfile.sparkFriends 保存 [{name, description}]。角色卡 / 系统备份沿现有角色保存链保留名单。Spark → 管理提供手动编辑及提取草稿；提取经现有 ContextBuilder 世界书管线，接受的条目必须附上包含姓名的逐字原文证据，仍需用户确认保存。

生成发帖只使用当前角色账号。评论和点赞只接受当前角色与其确认名单；朋友 charId 为空，以 friend 标记，绝不据同名去读取另一张角色卡的私聊 / 人设。未确认的随机路人与朋友被丢弃。帖子 friendLikes 保存具名且去重的朋友点赞。刷新动态可同时产生互动，详情的“刷新朋友互动”可追加互动。没有独立的闭页后台定时发帖服务。

## 生图服务

NaiState.provider 缺省 nai，可选 gpt；gptImage 保存官方 / 第三方两套独立凭据与模型，以及 GPT 尺寸和质量。模型可自填，第三方需支持 HTTPS Images API `/images/generations` 与浏览器跨域，返回 data[0].b64_json 或 HTTPS 图片 url。不是所有第三方聊天式生图接口都兼容。

NAI 保留原流程。GPT 复用场景、画师词和固定角色外貌的编译结果，只将提示词、GPT 模型、尺寸、质量、n=1 发给 GPT 接口。GPT 分支不校验 NAI 专用参数、不编码参考图、不调用 NAI，也不自动换服务或重试。原图经现有 blobRef 存储和相册 / 聊天路径保存；GPT 不写入虚假的 NAI seed。

提示词库便携导出剥离所有生图凭据；导入保留当前设备凭据，不自动打开角色生图。完整系统备份与原有 NAI 一样可能含 Key，应作为私人备份保存。

接口依据：[OpenAI 官方图像生成文档](https://developers.openai.com/api/docs/guides/image-generation)。接口可用性、模型权限、计费及第三方格式仍以用户所选服务为准。
